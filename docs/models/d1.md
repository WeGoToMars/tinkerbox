# d1-3B (`tinkerbox_ane.d1`)

[LiquidAI/d1-3B](https://huggingface.co/LiquidAI/d1-3B), a decision model fine-tuned from LFM2.5-VL-3B. Weights and upstream code are pinned to `LiquidAI/d1-3B@051bcc464b01b9f92942b364d9586b0ef5912432` under the [LFM Open License v1.0](../../LICENSES/LFM-Open-License-v1.0.txt). Converted bundles are published to [wegotomars/d1-3B-CoreAI-ANE](https://huggingface.co/wegotomars/d1-3B-CoreAI-ANE).

## Execution

FP16 backbone, 128-token chunks, 32,768-token context. The bundle keeps nine cache-tier functions with shared weights; the runtime requires the version 2 packed backbone, so older bundles must be re-exported and compiled.

| Stage | Runs on |
| --- | --- |
| Tokenization, image tiling, position-embedding interpolation | CPU |
| Token-embedding lookup | CPU |
| SigLIP2 vision tower (separate Core AI asset) | Neural Engine |
| Multimodal projector (FP32; Accelerate matrix unit) | CPU |
| LFM backbone with its convolution and attention state | Neural Engine |
| Answer readout over the option tokens | CPU |

The GPU stays idle.

## API

`system_one`, `system_one_batch`, `probabilities`, and `probabilities_batch` handle binary, choice, and score queries. `count_tokens` takes the same arguments as `system_one` and returns the `input_tokens` and `image_tiles` it would use, without running the model, and each picture's `images` layout: its tile grid, the size it is resized to, and its overview. Prompts exceeding 32,768 tokens are rejected.

## Images

Pass Pillow images with any request. Pictures above about half a megapixel are split into 512×512 tiles plus a thumbnail, as upstream; each tile is one vision pass and up to 256 tokens. `model.max_image_tiles` bounds the tiles per picture, from 1 (never split) to 10, and defaults to 6. The state may be `None` when the pictures carry the input.

```python
from PIL import Image
from tinkerbox_ane import d1

with d1.load() as model:
    result = model.system_one(None, {"receipt": {"type": "noul", "instructions": "Is this a receipt?"}},
                              images=[Image.open("photo.jpg")])
```

Image tokens join the shared trunk, so several questions about the same pictures encode them once.

The processor selects the tile grid based on aspect ratio rather than raw dimensions. The default limit of 6 tiles maintains coverage of the former one-megapixel ceiling across standard aspect ratios.

## Multiple decisions in one pass

The backbone mirrors upstream Torch: the state is a shared trunk, and each question is an isolated branch. Attention masks prevent questions from seeing each other, convolution windows restart from the trunk history, and RoPE positions restart at the end of the trunk for each branch. Several short decisions can share one ANE invocation; longer trees stream through 128-token chunks. Tree planning lives in `d1/tree.py`.

```python
with d1.load() as model:
    result = model.system_one("Hi", {
        "greeting": {"type": "noul", "instructions": "Is this a greeting?"},
        "refund": {"type": "noul", "instructions": "Is this a refund request?"},
    })
```

Single-question batch requests are packed too. Each logical prompt must fit the 32,768-token context; trees exceeding that physical token budget split into groups. Multi-question usage counts the state once plus all question suffixes, matching upstream.

Single decisions skip tree planning and reuse cached routing and causal masks in the native host, updating only newly visible history. Packed requests rebuild branch-specific metadata. Both paths execute the same ANE graph.

## Export and compile

```sh
uv run python -m tinkerbox_ane.d1.export
uv run python -m tinkerbox_ane.d1.compile
```

Export writes intermediate artifacts to `artifacts/build/d1_fp16_fused128_ctx32768`, and compilation produces the deployment bundle in `artifacts/d1_fp16_fused128_ctx32768`. Load the local result with `d1.load(d1.DEFAULT_ASSET)`.

Compiler options:
- `--force`: Rebuild an existing bundle. Each asset is verified before it replaces the previous one; if a later asset fails, rebuild again before using the directory.
- `--architecture <arch>`: Target a specific architecture instead of the current machine.
- `--allow-unsupported`: Attempt compilation for an architecture outside the verified support list.

## Publishing

```sh
# Compile bundles for specific architectures without uploading
uv run python -m tinkerbox_ane.d1.publish --arch h17s h16g --no-upload

# Publish prepared bundles and create a release tag
uv run python -m tinkerbox_ane.d1.publish --arch h17s h16g --upload-only --tag v2.0.0
```

Omitting `--arch` targets all supported architectures. The upload synchronizes the remote `macos27` tree with the selected architectures, pruning omitted targets and obsolete files while keeping existing release tags intact.

Options:
- `--arch`: Target architectures to build (defaults to all supported architectures).
- `--tag`: New release tag to create on Hugging Face (must not already exist).
- `--source`, `--staging`, `--repo`: Source export directory, local staging path, and Hugging Face repository.
- `--metadata`: Directory containing release metadata files (`LICENSE`, `NOTICE`, `README.md`).

After publishing, update the model's `revision` in `src/tinkerbox_ane/models.json`. (The legacy script `scripts/publish_all_chips.py` forwards to this CLI.) To use a compiled bundle before its tag is published:

```sh
uv run python -m tinkerbox_ane.install d1-3b artifacts/d1_fp16_fused128_ctx32768
```

## Validation

```sh
uv run python scripts/build_reference.py
uv run python -m tinkerbox_ane.d1.guard artifacts/validation/check -- uv run python scripts/validate.py
```

Reference generation downloads benchmark inputs and runs the official FP32 CPU model. Validation checks prompt tokens and probabilities across all nine cache capacities against that reference.
