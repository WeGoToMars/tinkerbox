# d3-nano and d3-mini

[vllm-sr/d3-nano](https://huggingface.co/vllm-sr/d3-nano) and
[vllm-sr/d3-mini](https://huggingface.co/vllm-sr/d3-mini) answer yes/no, choice,
and scoring questions about text and images.

Requires macOS 27 and Apple M4 or newer. Install the
[Tinkerbox app or Python package](../../README.md#quickstart);
model files download automatically on first use.

| Model ID | Download | Measured peak wired memory |
| --- | ---: | ---: |
| `d3-nano` | About 4.5 GB | 3.8 GiB |
| `d3-mini` | About 9.2 GB | 9.0 GiB |

Memory measurements are from M5 Pro. Other supported chips are cross-compiled;
on-device performance has been checked on M5 Pro only.

## Usage

Choose either model on the app's Decision screen. In Python:

```python
import tinkerbox_ane

with tinkerbox_ane.load("d3-nano") as model:
    result = model.system_one("I was charged twice this month.", {
        "refund": {"type": "noul", "instructions": "Is this a refund request?"},
    })
    print(result["answers"])
```

Use `"d3-mini"` to select the larger model. Both support `system_one`,
`system_one_batch`, `probabilities`, `probabilities_batch` and `count_tokens`.

Each question requires a separate pass. Multiple questions and batched inputs
run in order, and the Python API warns when a call needs several passes.
For several questions about the same input, [d1-3B](d1.md) supports shared passes.

## Images and limits

Pass Pillow images, image paths or URLs through `images`. Text may be `None`
when an image supplies the input. Images retain their aspect ratio.

The context limit is **32,768 tokens**, including questions and image tokens.
Use `count_tokens` to preview usage before running a request.

`model.max_image_tokens` sets the per-image detail budget, from 64 to 1,600
(default 1,600). Lower values reduce image processing time. The app exposes
this under **Model Settings**.

Model weights and upstream code use [Apache-2.0](../../LICENSES/Apache-2.0.txt).
[Developer build and validation commands](../model-publishing.md#model-builds).
