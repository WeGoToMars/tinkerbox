# d3-nano and d3-mini (`tinkerbox_ane.d3`)

[vllm-sr/d3-nano](https://huggingface.co/vllm-sr/d3-nano) and [vllm-sr/d3-mini](https://huggingface.co/vllm-sr/d3-mini), decision models fine-tuned from Qwen3.5-2B and Qwen3.5-4B. Both share one Qwen3.5 implementation. Weights and upstream code are pinned in `src/tinkerbox_ane/d3/__init__.py` and licensed under [Apache-2.0](../../LICENSES/Apache-2.0.txt). Converted bundles are published to [wegotomars/d3-nano-CoreAI-ANE](https://huggingface.co/wegotomars/d3-nano-CoreAI-ANE) and [wegotomars/d3-mini-CoreAI-ANE](https://huggingface.co/wegotomars/d3-mini-CoreAI-ANE). Each bundle's `checkpoint` folder holds the upstream code, tokenizer, configurations and readout, and of the weights only the token embeddings and the vision position table (1.05 GB for d3-nano, 1.30 GB for d3-mini), so loading needs nothing else from upstream.

| Model | Context | Layers |
| --- | ---: | ---: |
| `d3-nano` | 32,768 tokens | 24 (6 stages) |
| `d3-mini` | 32,768 tokens | 32 (8 stages) |

## Execution

FP16 stages in 128-token chunks. These checkpoints use `noncausal_full_attention`: every fourth layer is full attention over the whole prompt, the Gated DeltaNet layers in between stay causal. Each bundle stage is one asset holding the DeltaNet layers before a full-attention layer and that layer, with shared weights, as three kinds of function:

- `prompt{stage}c{width}` runs a whole prompt of up to 320 tokens through the stage in one call, at widths of 128, 192, 256 and 320 tokens. The scan runs in 128-token chunks plus a final 64-token chunk, from an empty state, and the keys and recurrent state stay on the Neural Engine.
- `scan{stage}` scans one 128-token chunk from a recurrent state and returns its keys.
- `attend{stage}c{capacity}` runs the full-attention layer for one chunk at each attention capacity.

Longer prompts run layer-major: a stage scans every chunk and collects the complete prompt's keys, then attends every chunk, before the next stage starts.

| Stage | Runs on |
| --- | --- |
| Tokenization, image resizing and patching, position and rotary tables | CPU |
| Token-embedding lookup | CPU |
| Qwen3.5 vision tower and merger (separate Core AI asset) | Neural Engine |
| Gated DeltaNet scans and full-attention layers | Neural Engine |
| Decision readout and softmax (FP32) | CPU |

The GPU stays idle.

## One question per pass

Full attention lets every prompt token see the question at the end of the prompt, so no part of the prompt is independent of the question. Questions cannot share a trunk as d1's do. The catalog lists both models with `question_trees: false`, and:

- A call with several questions, or a batch of several requests, runs one pass per question, in order. Each reads its whole prompt, so time grows with every question. The call emits `tinkerbox_ane.d3.runtime.SequentialQuestionsWarning`.
- `usage.input_tokens` counts each question's whole prompt.
- The app shows "No parallel decisions" instead of the Parallel/Sequential switch. It sends the questions together so pictures are encoded once, and displays the answers when the request finishes.

```python
import tinkerbox_ane

with tinkerbox_ane.load("d3-nano") as model:
    result = model.system_one("I was charged twice this month.", {
        "refund": {"type": "noul", "instructions": "Is this a refund request?"},
    })
```

## API

`system_one`, `system_one_batch`, `probabilities`, `probabilities_batch` and `count_tokens` match the other decision models. Answers are formatted by the checkpoint's own code, as upstream. Prompts over the bundle's context are rejected before anything runs.

Each `system_one` result's `usage` also reports its request's compute:

- `neural_engine_ms` is the time spent in Neural Engine calls, vision passes included.
- `flops` counts the FLOPs, two per multiply-add, of the functions those calls ran (matmuls, convolutions and attention), padding and masked keys included.

Export counts each function's FLOPs from the PyTorch graph's shapes, with fake tensors and no arithmetic, and writes them to the manifest beside its functions (`flops` in each stage asset, `vision_flops` for the tower). The counts leave out elementwise work and are the same for every architecture. The runtime rejects a bundle without them. `flops / neural_engine_ms` is the compute rate the app shows beside the run time.

## Images

Pass Pillow images, local paths or URLs; the state may be `None`. Images are processed by the checkpoint's own Qwen processor: each keeps its shape and is resized to multiples of 32 pixels, one token per 32 × 32 block, within the official 1.6-megapixel budget (1,600 tokens). `model.max_image_tokens`, from 64 to 1,600, lowers that budget. Text positions follow the official multimodal rotary index.

The vision tower is exported at seven patch capacities, from 1,024 to 6,400 patches (256 to 1,600 tokens); the bundle manifest lists them. Each image runs once at the smallest capacity that holds it. The host computes its interpolated position embeddings and rotary tables, and padding patches are masked out. The tower runs channels first with 1 × 1 convolutions. Attention runs in four groups of heads and, above 2,048 patches, in blocks of query rows; a row of ones under the values sums the softmax weights in the same product. LayerNorm divides each patch by 32 times its mean absolute deviation before squaring, since the residual stream reaches thousands, beyond FP16's range once squared. Several questions about the same pictures encode them once.

## Export and compile

```sh
uv run python -m tinkerbox_ane.d3.export d3-nano --out artifacts/build/d3-nano
uv run python -m tinkerbox_ane.d3.compile artifacts/build/d3-nano --out artifacts/d3-nano
uv run python -m tinkerbox_ane.install d3-nano artifacts/d3-nano
```

Use `d3-mini` the same way. Compilation defaults to this Mac's architecture; pass `--architecture` to cross-compile. Cross-compilation verifies full ANE placement but not correctness or performance on that device. On macOS 27.0.1, `ANELargeModelCompilerService` crashes at random with a memory tag-check fault, failing about one stage in six; the same command resumes, keeping the stages already verified. Each process's first load also compiles on the device, cached per code-signing identifier, and can hit the same crash. After repeated crashes, launchd holds the service back for 20 minutes.

## Publishing

```sh
uv run python -m tinkerbox_ane.d3.publish d3-nano --source artifacts/build/d3-nano --no-upload
uv run python -m tinkerbox_ane.d3.publish d3-nano --source artifacts/build/d3-nano --upload-only
```

## Validation

```sh
uv run python scripts/validate_d3.py --write-reference d3-nano --reference artifacts/reference-d3-nano-cases.json
uv run python scripts/validate_d3.py --smoke --asset artifacts/d3-nano --reference artifacts/reference-d3-nano-cases.json \
  --out artifacts/validation/d3-nano.json
D3_NANO_ASSET=artifacts/d3-nano D3_MINI_ASSET=artifacts/d3-mini uv run pytest -q tests/test_d3_runtime.py
```

Acceptance requires the pinned official FP32 CPU reference, exact text prompt IDs, and coverage of every reachable attention capacity and short-prompt width. `--smoke` allows a partial set to exit successfully on numerical checks; its report keeps `passed: false` until acceptance coverage is complete. Each measured text/vision path is warmed before timing.

Without `--questions`, the reference holds official FP32 CPU probabilities for a small built-in set of text prompts of 95–813 tokens and image prompts: solid and striped pictures at 4:3, 1:3, 3:1 and square shapes, up to 1.2 MP, and two pictures in one prompt. Validation requires matching token counts, 97% agreement on answers, a maximum probability drift of 0.1 and a mean of 0.005. d1 gates its maximum drift at 0.05. d3's gate is looser because the Neural Engine runs the Gated DeltaNet recurrence in FP16, while upstream keeps it in FP32.

FP32 references run the official model with each decoder layer's BF16 weights converted to FP32 only while that layer runs. FP32 holds every BF16 value, so the probabilities are bit-identical to a fully FP32 model's, at about half the memory: d3-mini's reference fits in 24 GB.

d1's 204 decisions (`scripts/build_reference.py` writes them to `artifacts/reference.json`) also serve as a d3 set: public benchmarks, a short prompt and long needle prompts, those within the model's context. `--dtype bfloat16` writes the same reference at upstream's default precision, and `--baseline` reports its drift beside the bundle's:

```sh
uv run python scripts/validate_d3.py --write-reference d3-nano --questions artifacts/reference.json \
  --reference artifacts/reference-d3-nano.json
uv run python scripts/validate_d3.py --write-reference d3-nano --questions artifacts/reference.json \
  --dtype bfloat16 --reference artifacts/reference-d3-nano-bf16.json
uv run python scripts/validate_d3.py --asset artifacts/d3-nano --reference artifacts/reference-d3-nano.json \
  --baseline artifacts/reference-d3-nano-bf16.json --out artifacts/validation/d3-nano-204.json
```

Each tier must also agree on 96% and keep a mean drift within 0.01. On an M5 Pro (`h17s`), d3-nano's 203 decisions in context (one long prompt has 32,832 tokens) against official FP32:

| Prompt tokens | Decisions | ANE agreement | ANE mean / max drift | Official BF16 mean / max drift |
| --- | ---: | ---: | ---: | ---: |
| ≤256 | 132 | 100% | 0.0033 / 0.087 | 0.0014 / 0.025 |
| 257–512 | 28 | 96.4% | 0.0029 / 0.029 | 0.0010 / 0.006 |
| 513–32,768 | 43 | 100% | ≤0.0008 / 0.002 | ≤0.0021 / 0.002 |
| All | 203 | 99.5% | 0.0027 / 0.087 | 0.0011 / 0.025 |

Labelled accuracy is 58.6% on the ANE and 59.1% for FP32. The largest drifts are two MMLU prompts of 128 and 132 tokens, at 0.085 and 0.087, and neither changes the answer. The one disagreement is a 320-token Yelp review whose top two scores differ by 0.01. Short prompts drift about twice as much as upstream BF16, which keeps the Gated DeltaNet recurrence and its gated norm in FP32; the Neural Engine computes in FP16 throughout, and every primitive measured stays within about four times FP16 rounding. Long prompts drift as little as BF16.

d3-mini runs the same commands. Its 203 decisions in context, against official FP32:

| Prompt tokens | Decisions | ANE agreement | ANE mean / max drift | Official BF16 mean / max drift |
| --- | ---: | ---: | ---: | ---: |
| ≤256 | 132 | 100% | 0.0009 / 0.025 | 0.0007 / 0.018 |
| 257–512 | 28 | 100% | 0.0011 / 0.016 | 0.0009 / 0.007 |
| 513–4,096 | 28 | 100% | ≤0.0001 / 0.0003 | ≤0.0001 / 0.006 |
| 4,097–32,768 | 15 | 100% | ≤0.0001 / 0.0001 | ≤0.0001 / 0.0001 (10 prompts) |
| All | 203 | 100% | 0.0008 / 0.025 | 0.0006 / 0.018 (198 prompts) |

Labelled accuracy is 65.0% on the ANE and for FP32. The largest drift is a 145-token MMLU prompt at 0.025. The BF16 reference covers the long prompts up to 6,207 tokens. d3-mini drifts about as much as upstream BF16; on the built-in cases, its mean and maximum drift are 0.0005 and 0.0039.

d3-nano's vision tower features differ from official FP32 less than official BF16's: on generated pictures of 300–768 tokens, the mean token error relative to the median token norm is 0.046–0.065, against 0.054–0.074 for BF16.

## Performance

Measured on an M5 Pro (`h17s`) with one question, warm, from Python. Energy is the Neural Engine's average power from `powermetrics` over back-to-back decisions, times the mean decision time.

| Prompt tokens | Latency | ANE energy |
| ---: | ---: | ---: |
| 91 (shortest) | 31 ms | 121 mJ |
| 124 | 32 ms | 124 mJ |
| 188 | 56 ms | 191 mJ |
| 252 | 64 ms | 250 mJ |
| 316 | 89 ms | 317 mJ |
| 508 | 137 ms | 499 mJ |
| 1,020 | 279 ms | 1.0 J |
| 4,092 | 1.19 s | 4.3 J |

| Picture | Image tokens | Vision pass | Decision | ANE energy |
| --- | ---: | ---: | ---: | ---: |
| 640 × 480 | 300 | 0.28 s | 0.42 s | 0.5 J |
| 1024 × 768 | 768 | 0.90 s | 1.16 s | 1.1 J |
| 1600 × 1000 | 1,550 | 4.1 s | 4.6 s | 3.3 J |

The vision tower's attention is bound by memory traffic: the Neural Engine draws 0.7–1.2 W during a vision pass, against about 3.6 W for text. `max_image_tokens` trades detail for time.
