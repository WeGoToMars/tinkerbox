# d3-nano and d3-mini (`tinkerbox_ane.d3`)

[vllm-sr/d3-nano](https://huggingface.co/vllm-sr/d3-nano) and [vllm-sr/d3-mini](https://huggingface.co/vllm-sr/d3-mini), decision models fine-tuned from Qwen3.5-2B and Qwen3.5-4B. Both share one Qwen3.5 implementation. Weights and upstream code are pinned in `src/tinkerbox_ane/d3/__init__.py` and licensed under [Apache-2.0](../../LICENSES/Apache-2.0.txt). Converted bundles are published to [wegotomars/d3-nano-CoreAI-ANE](https://huggingface.co/wegotomars/d3-nano-CoreAI-ANE) and [wegotomars/d3-mini-CoreAI-ANE](https://huggingface.co/wegotomars/d3-mini-CoreAI-ANE).

| Model | Context | Layers |
| --- | ---: | ---: |
| `d3-nano` | 32,768 tokens | 24 (6 stages) |
| `d3-mini` | 4,096 tokens | 32 (8 stages) |

## Execution

FP16 stages in 128-token chunks. These checkpoints use `noncausal_full_attention`: every fourth layer is full attention over the whole prompt, the Gated DeltaNet layers in between stay causal. Each bundle stage is one asset holding a scan of the DeltaNet layers before a full-attention layer and that layer's attention at each capacity, with shared weights. The native host runs layer-major: a stage scans every chunk and collects the complete prompt's keys, then attends every chunk, before the next stage starts.

| Stage | Runs on |
| --- | --- |
| Tokenization, image resizing and patching, position and rotary tables | CPU |
| Token-embedding lookup | CPU |
| Qwen3.5 vision tower and merger (separate Core AI asset) | Neural Engine |
| Gated DeltaNet scans and full-attention layers | Neural Engine |
| Decision readout and softmax (FP32) | CPU |

The GPU stays idle.

## One question per pass

Full attention lets every prompt token see the question at the end of the prompt, so no part of the prompt is independent of the question. Questions cannot share a trunk as d1's do. The catalog lists both models with `question_trees: false`, and:

- A call with several questions, or a batch of several requests, runs one pass per question, in order. Each reads its whole prompt, so time grows with every question. The call emits `tinkerbox_ane.d3.runtime.SequentialQuestionsWarning`.
- `usage.input_tokens` counts each question's whole prompt.
- The app shows "No parallel decisions" instead of the Parallel/Sequential switch.

```python
import tinkerbox_ane

with tinkerbox_ane.load("d3-nano") as model:
    result = model.system_one("I was charged twice this month.", {
        "refund": {"type": "noul", "instructions": "Is this a refund request?"},
    })
```

## API

`system_one`, `system_one_batch`, `probabilities`, `probabilities_batch` and `count_tokens` match the other decision models. Answers are formatted by the checkpoint's own code, as upstream. Prompts over the bundle's context are rejected before anything runs.

## Images

Pass Pillow images, local paths or URLs; the state may be `None`. Images are processed by the checkpoint's own Qwen processor: each keeps its shape and is resized to multiples of 32 pixels, one token per 32 × 32 block, within the official 1.6-megapixel budget (1,600 tokens). `model.max_image_tokens`, from 64 to 1,600, lowers that budget. Text positions follow the official multimodal rotary index.

The vision tower is exported at four patch capacities (1,024, 2,048, 4,096 and 6,400 patches, or 256 to 1,600 tokens). Each image runs once at the smallest capacity that holds it. The host computes its interpolated position embeddings and rotary tables, and padding patches are masked out. Above 2,048 patches, attention runs in blocks of query rows, which is exact and stays within what the ANE compiles. Several questions about the same pictures encode them once.

## Export and compile

```sh
uv run python -m tinkerbox_ane.d3.export d3-nano --out artifacts/build/d3-nano
uv run python -m tinkerbox_ane.d3.compile artifacts/build/d3-nano --out artifacts/d3-nano
uv run python -m tinkerbox_ane.install d3-nano artifacts/d3-nano
```

Use `d3-mini` the same way. Compilation defaults to this Mac's architecture; pass `--architecture` to cross-compile. Cross-compilation verifies full ANE placement but not correctness or performance on that device.

## Publishing

```sh
uv run python -m tinkerbox_ane.d3.publish d3-nano --source artifacts/build/d3-nano --no-upload
uv run python -m tinkerbox_ane.d3.publish d3-nano --source artifacts/build/d3-nano --upload-only
```

The repository and tag default to the catalog entry. Options match [d1's](d1.md#publishing).

## Validation

```sh
uv run python scripts/validate_d3.py --write-reference d3-nano --reference artifacts/reference-d3-nano-cases.json
uv run python scripts/validate_d3.py --asset artifacts/d3-nano --reference artifacts/reference-d3-nano-cases.json \
  --out artifacts/validation/d3-nano.json
D3_NANO_ASSET=artifacts/d3-nano D3_MINI_ASSET=artifacts/d3-mini uv run pytest -q tests/test_d3_runtime.py
```

Without `--questions`, the reference holds official FP32 CPU probabilities for a small built-in set of text prompts of 95–813 tokens and image prompts: solid and striped pictures at 4:3, 1:3, 3:1 and square shapes, up to 1.2 MP, and two pictures in one prompt. Validation requires matching token counts and answers, a maximum probability drift of 0.05 and a mean of 0.005.
